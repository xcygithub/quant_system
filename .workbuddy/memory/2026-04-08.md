## position_sizer.py bug 修复 (2026-04-08 下午)
**问题**: 多股票回测中，000001.SH（上证指数）有买入信号但始终没有被交易

**诊断过程**:
1. 确认 000001.SH 有 175 个买入信号（不是信号问题）
2. 确认 `diagnose_web_backtest.py` 中 000001.SH 交易记录为 0
3. 对比 `debug_selection_at_rebalance.py` 发现 000001.SH 有 26 次交易
4. 发现差异在 `position_method='equal_weight'` vs `'equal'`
5. 最终定位到 `max_single_position=0.2` 导致高价股票无法买入

**根本原因**:
- `max_single=0.2` 时，100万 × 20% = 20万/只
- 000001.SH 价格 2700~3500 点，买入100股需要 27万~35万
- 20万 < 27万，无法购买1手（100股），`shares=0`

**修复方案**:
在 `PositionSizer.allocate()` 方法中添加逻辑：
1. 首次分配时记录所有 `shares=0` 的股票索引
2. 计算释放的权重总和
3. 清零这些无法买入的股票的权重
4. 按权重比例将释放的权重分配给其他能买入的股票

**验证结果**:
- `max_single=0.2`: 000001.SH 仍为0（金额确实不够买1手）
- `max_single=0.3`: 000001.SH 有25次交易 ✅
- `max_single=0.4`: 000001.SH 有123次交易

**用户解决方案**: 在Web界面将「单只最大仓位」设置为30%或更高

## 数据未更新问题 (2026-04-08 15:51)
**问题**: 自选股数据最新只到 2026-04-03，缺少 4月7日的数据

**根因**: `_check_data_complete` 方法的估算逻辑有漏洞
- 估算公式：交易日 ≈ 日历天 × 0.4
- 从 2026-03-01 到 2026-04-08 约 38 天，估算交易日 = 15 天
- 85% 阈值 = 12.75
- 数据库有约 22 条数据（3月完整数据），满足阈值，判断为"完整"
- 但清明节假期（4月4-6日）导致实际交易日比估算少 3 天

**症状**: 数据库缓存判断为完整，不触发重新获取，导致数据停留在 4-03

**临时解决方案**: 手动删除数据库中 3-4 月数据，强制重新获取
```python
# 删除指定股票的数据
DELETE FROM daily_kline WHERE symbol='000001.SH' AND date >= '2026-03-01'
```

**根本改进方向**: `_check_data_complete` 应该对比"数据库最新日期"与"请求的结束日期"，而不是仅依赖数据条数估算
- 如果数据库最新日期 < 结束日期 - N天，就应该重新获取
- N 应该是一个较小的缓冲值（如 3 天），考虑到假期等因素

## 多股票回测卖出机制分析 (2026-04-08 17:30)

### 两个卖出机制导致股票持有一天就被卖出

**机制1：每日卖出信号检查**
- 文件：`portfolio/multi_stock_backtest.py`
- 位置：第332-355行 `_check_sell_signals` 方法
- 逻辑：每个交易日都检查持仓股票的信号，只要 `signal_val < 0` 就立即平仓
- **问题**：没有任何持有天数限制，信号变-1就立即卖

**机制2：调仓时强制换股**
- 文件：`portfolio/multi_stock_backtest.py`
- 位置：第357-394行 `_rebalance` 方法
- 逻辑：调仓时重新选股，只要持仓股票不在新候选列表中就卖出
- **问题**：即使股票信号还是买入，只要得分下降不在候选中就被强制卖出

**调仓周期参数 `rebalance_days` 的作用**：
- 控制多久进行一次重新选股（第248行）
- 但每日卖出信号检查（第252行）不受此参数控制

**解决方案**：
- 在 `_check_sell_signals` 中增加 `MIN_HOLDING_DAYS` 约束
- 或改用更长期的均线参数减少信号频繁切换

## 候选列表的确定流程 (2026-04-08 17:57)

### 调仓时候选列表的生成过程

**第一步：调仓触发条件（run方法 第248-256行）**
- `should_rebalance = (i - self.last_rebalance_day) >= self.rebalance_days`
- `needs_initial_position = (len(self.positions) == 0 and self.cash > 0)`
- 满足条件时调用 `_rebalance()`

**第二步：`_rebalance` 调用 `_select_candidates`（第357-394行）**
```python
new_candidates = self._select_candidates()
target_symbols = {score.symbol for score in new_candidates}
to_sell = current_symbols - target_symbols  # 只要不在候选中就卖！
```

**第三步：`_select_candidates` 逻辑（第396-422行）**
1. 准备所有股票数据（需要 >=20 天数据）
2. 对所有股票打分
3. 按综合得分排序，取 Top N（默认 max_positions=5）

**第四步：评分体系（selector.py 第82-131行）**

| 维度 | 计算方式 | 权重 |
|------|----------|------|
| 动量得分 | 5日、10日、20日收益率加权 | 30% |
| 信号强度得分 | 最新信号(buy/sell/hold)和信号一致性 | 30% |
| 波动率得分 | 波动率越低得分越高 | 20% |
| 流动性得分 | 日均成交额越高得分越高 | 20% |

综合得分 = 动量×0.3 + 信号×0.3 + 波动率×0.2 + 流动性×0.2

### 关键问题

**问题：每次调仓都是重新对所有股票打分排序**

即使持仓股票的信号还是 `buy`，但因为：
- 动量下降
- 其他股票涨得更好
- 波动率/流动性拖后腿
- 综合得分掉到 Top N 之外

→ 立即被卖出，换成得分更高的股票

### 结论
卖出不是因为"信号变差"，而是因为"得分排名下降"——这是更频繁换股的根源。
