### 仓位分配参数失效Bug修复

**问题**：用户在Web界面设置了"单只最大仓位20%"和"最大总仓位80%"，但回测结果显示满仓买了单只股票。

**原因**：`portfolio/position_sizer.py` 中的"权重重新分配"逻辑存在bug。当某只股票因价格太高无法购买100股时，它的权重被释放并加给其他股票，但重新分配时没有检查 `max_single_position` 限制，导致某些股票的仓位超过了20%限制。

**修复**：
- 移除了权重重新分配逻辑
- 无法购买100股的股票直接将其仓位设为0
- 确保每只股票仓位严格不超过 `max_single_position` 限制

**修改文件**：`portfolio/position_sizer.py`

**副作用**：修复后总仓位可能略低于设定的80%（因为高价股的权重被放弃）。

### 仓位超限根因修复：累计持仓检查 + 差额买入

**问题**：之前的修复（单次买入金额检查）治标不治本。用户设20%仓位限制，但多次调仓后同一股票累计仓位达到100%。

**根本原因**（两个bug叠加）：
1. `_buy()` 方法只检查单次买入金额，不检查累计持仓市值
2. `_rebalance()` 方法给已持仓的股票分配完整目标仓位，而不是只分配差额

**复现路径**：
- 初始100万，max_single_position=20%，max_positions=1
- 第1次调仓：position_sizer 分配20% → 买入20万 → 持仓20万
- 第2次调仓：position_sizer 又分配20%（基于总资产100万×20%=20万）→ _buy 检查本次20万没超限 → 加仓 → 持仓40万
- 如此反复5次 → 持仓100万

**修复**：
1. **`_buy()` 累计持仓检查**：改为 `current_holding_value + amount > max_single_amount`
   - 先计算已有持仓市值 `current_holding_value`
   - 计算剩余可买金额 `available_buy_amount = max_single_amount - current_holding_value`
   - 超限则调整数量，已满则直接 return

2. **`_rebalance()` 差额买入**：改为 `target_amount - current_holding`
   - 计算目标持仓金额 `target_amount = total_assets * alloc.weight`
   - 扣除已有持仓市值 `current_holding`
   - 只买入差额部分 `buy_amount_needed`
   - 差额<=0时跳过（已满仓）

**修改文件**：`portfolio/multi_stock_backtest.py`

**验证**：4个单元测试全部通过（tests/test_position_limit.py）：
- 单只股票最大仓位 19.04%，不超20%
- 多只股票最大仓位 19.84%，违规0次
- _buy 累计检查：已持仓20%时再加仓被阻止
- _rebalance 差额买入：已满仓时不重复分配
