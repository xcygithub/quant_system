## ISSUE-20260505-01 因子覆盖率不足导致多因子回测失败

- 状态：待解决
- 优先级：高
- 影响范围：`web/factor_backtest_page.py`、`web/services/backtest_service.py`、多因子回测流程

### 现象

- 多因子回测在执行时提示：`因子覆盖率不足: 90.05% < 95.00%`。
- 即使日线行情已补齐到回测区间，仍会因因子数据缺失而中断。

### 已定位结论

- 回测校验的是“因子面板覆盖率”，不是仅校验日线数据。
- 当前主要缺口来自基本面/估值相关因子（如 `roe`、`revenue_growth`、`pe`、`pb`）。
- 技术因子（如 `momentum_20`）覆盖率相对较高。
- 若启用 `turnover_rate`，覆盖率可能进一步下降（历史区间缺失显著）。

### 复现条件

1. 进入多因子回测页面。
2. 选择包含基本面与估值因子的组合。
3. 回测起止覆盖 2023 年及以后较长区间。
4. 运行回测，触发覆盖率校验失败。

### 临时绕行方案

- 降低 `min_factor_coverage` 阈值（例如从 `0.95` 调整到 `0.90`）。
- 暂时移除缺失率较高的因子（特别是 `turnover_rate`）。

### 建议长期方案

1. 增加“分因子覆盖率诊断面板”，在运行前展示每个因子的覆盖率与缺失时段。
2. 增加“自动降级策略”：
   - 先按高阈值校验；
   - 失败后建议移除最差因子，支持一键重跑。
3. 建立因子历史补齐任务：
   - 对 `factor_values` 与估值相关表执行批量补齐；
   - 补齐后落库，减少运行时逐日兜底计算。
4. 在 UI 中显式展示“请求回测区间 vs 实际有效区间 vs 因子有效区间”。

### 验收标准（建议）

- 在默认股票池与默认多因子配置下，回测可稳定通过覆盖率校验。
- 因子覆盖率不足时，页面可明确给出“缺哪个因子、缺在哪个时间段、建议怎么处理”。
